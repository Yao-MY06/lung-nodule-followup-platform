# F3 复查对比与计划自适应（≥2mm 规则 / 升级预警）

> 文档类型：跨模块流程　所属模块：nodule+followup+notification　依赖文档：[global/30, modules/nodule §4, modules/followup §4]
> 版本：v1.0（2026-08-22）　阅读优先级：高　风险车道：黄区（临床决策辅助）

## 流程目标

复查结果录入后自动完成：结节纵向对比 → 进展判定（≥2mm 规则）→ 随访计划自适应（升级/续期/降级）→ 必要时预警医生。

## 主链路

```
医生端录入复查快照 POST /api/nodule/snapshots
  → nodule：写 nodule_snapshot
  → 与上一条快照对比(同 nodule_id 最近两条):
       Δmax_diameter_mm / Δsolid_diameter_mm / 密度变化 / is_new
  ├─ 判定"稳定" → compare 返回建议"按原计划继续"
  ├─ 判定"进展"(任一径增大 ≥2mm)
  │    → 发 YILIAO_NODULE_PROGRESS{patientId, noduleId, delta...}
  │    → followup 消费: 以【最新快照特征】重新匹配 decision_rule
  │         命中更高优先级规则(更短间隔) → 重算剩余任务(plan 内 adjust_reason="结节进展自动升级")
  │         无更高级规则 → 维持并在任务备注提示医生复核
  │    → notification 消费同一事件: 预警推送主管医生(站内信+摘要)
  └─ 报告结论"高度疑恶性" → 不自动改计划，仅标记 + 预警，
       转诊/MDT 由医生人工决策(扩展模块)
  → 任务完成流: 医生提交 followup_record → task.status=3
       → 按"当前最新特征+本次结果"匹配规则生成下一期任务(支持稳定后降级)
```

## 关键设计决策

| 决策 | 理由 |
|---|---|
| 对比逻辑在 nodule（数据owner），升级决策在 followup（规则owner） | 数据与规则职责分离；nodule 不懂随访间隔，followup 不算直径差 |
| 升级=重算剩余任务而非重建计划 | 保留计划连续性与历史任务（审计/趋势）；uk_patient_active 不受影响 |
| "稳定"也可能降级 | 任务完成时按最新特征重新匹配，pGGN 稳定 2 年可转年度——规则引擎天然支持 |
| 疑恶性不自动升级 | 升级随访间隔有指南依据可自动化；转诊是临床决策，系统只预警不代决策 |

## 异常场景

- 事件消费失败：重试 3 次进死信 + 告警；compare 接口结果不受影响（对比判定已在 nodule 本地完成）。
- followup 规则匹配无更高级规则：不改动任务，记录"建议医生复核"备注——**禁止**无依据缩短间隔。
- 快照无基线（首条）：只建基线，不对比不发事件。
