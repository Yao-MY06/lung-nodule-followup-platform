# F1 建档与计划生成（含 AI 抽取前置）

> 文档类型：跨模块流程　所属模块：nodule+ai+patient+followup+notification　依赖文档：[global/30, modules/ai, modules/nodule, modules/patient, modules/followup]
> 版本：v1.0（2026-08-22）　阅读优先级：高　风险车道：黄区（Seata 唯一链路）

## 流程目标

医生粘贴 CT 报告 → AI 抽取草稿 → 人工确认 → 建档 → 规则引擎自动生成随访计划 → 排程提醒。这是**答辩演示主线**与 Seata 唯一使用场景。

## 时序

```
医生端          nodule/ai                patient(TM)         followup          notification
  │ 1.粘贴CT报告原文
  ├─▶ ai-service POST /report/extract
  │      ├─ 脱敏过滤(姓名/证件/手机号)
  │      └─ LLM 结构化输出 → NoduleExtract 草稿(缺失=null禁臆造)
  │ 2.医生核对草稿、补危险因素 → 确认
  ├─▶ nodule POST /exam/reports/{id}/confirm      # extract_status 0→2
  │ 3.提交建档（触发 Seata 全局事务 XID）
  ├─▶ patient POST /archives ──── Seata AT ────┐
  │      ├─ patient: 写 patient_archive + risk_factor(+diagnosis)
  │      ├─ nodule:   写 nodule + 首条 nodule_snapshot（同一 XID 分支）
  │      └─ followup: 规则匹配 → followup_plan + 未来任务（同一 XID 分支）
  │ 4.事务提交成功
  │      ├─ nodule 发 YILIAO_EXTRACT_CONFIRMED（确认事件）
  │      └─ patient 发 YILIAO_ARCHIVE_CREATED（兜底对账事件）
  │                              followup 消费确认事件:
  │                                若 Seata 分支已生成计划 → 幂等跳过
  │                                若计划缺失(异常场景) → 立即补生成
  │ 5.followup 发 YILIAO_PLAN_CREATED ──────────────▶ 为每个 task 投递
  │     T-7/T-3/T-1 RocketMQ 定时消息(bizKey=taskId:remindType)
```

## 关键设计决策

| 决策 | 理由 |
|---|---|
| AI 抽取在建档**前**（独立步骤），不在 Seata 事务内 | LLM 调用慢且可能失败，不能拖长全局事务锁；抽取失败不阻塞建档（可手动录入） |
| 计划生成放在 Seata 分支内（Seata 内不做规则重算，只做模板匹配+插表） | 建档成功即有计划，用户体验完整；规则匹配输入来自确认后的表单数据 |
| ARCHIVE_CREATED 兜底事件与 Seata 并存 | 消息可能丢、事务可能回滚——幂等事件保证最终一定有计划；bizKey=patientId 防重复 |
| TM 在 patient-service | 建档 API 是事务发起方与用户入口 |

## 异常与回滚

- 任一分支失败：Seata 全局回滚（archive/nodule/plan 全部撤销），返回明确错误码，前端提示重试；**无部分成功状态**。
- Seata 服务不可用（开发期常见）：降级开关（Nacos `seata.enabled=false`）→ patient 本地事务 + 完全依赖 ARCHIVE_CREATED 事件异步生成计划；毕设演示需在验证报告注明所处模式。
- MQ 发送失败：本地事务已提交，事件丢失由 XXL-Job 每日对账（无计划且有档案的患者补生成）。

## 验证清单

- [ ] 抽取草稿字段与报告原文一致（缺失=null）
