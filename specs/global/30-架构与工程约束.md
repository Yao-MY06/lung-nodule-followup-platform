## 2. 工程结构（Maven 单仓多模块）

```
yiliao-parent
├── docker/               # docker-compose(中间件) + init-sql/ 按库分文件
├── yiliao-common/        # core / web / data / security【红区】 / mq / feign
├── yiliao-api/           # Feign 契约 + DTO，按 com.yiliao.api.{service} 分包
├── yiliao-gateway(8080) yiliao-auth(8081) yiliao-patient(8082) yiliao-nodule(8083)
├── yiliao-followup(8084) yiliao-notification(8085) yiliao-ai(8086)
├── yiliao-statistics(8087) yiliao-file(8088)
└── yiliao-ui/            # Vue3 + Element Plus（P2 起并行）
```

- 坐标：`groupId=com.yiliao`；包根 `com.yiliao.{module}`；启动类 `Yiliao{Xxx}Application`。
- 服务内分层：`controller / service(+impl) / mapper / entity / dto / convert(MapStruct) / config / listener(MQ) / job(XXL-Job) / feign(契约实现)`。

## 3. 模块依赖规则（违反即结构缺陷）

1. 服务模块只依赖 `yiliao-common-*` 与 `yiliao-api`；**服务之间禁止直接依赖**，只经 Feign 契约或 MQ 交互。
2. `yiliao-api` 只依赖 `common-core` + OpenFeign/Spring Web 注解，禁止携带实现与重依赖。
3. `common-*` 之间只允许依赖 `common-core`；common 层禁止出现业务概念（patient/nodule 等实体不进 common）。
4. 契约变更（`yiliao-api`、`common-mq` 事件类）按**黄区**处理：先改契约 → 提供方/调用方同步，禁止单侧偷改。

## 4. 数据库拆分（每服务一库，禁止跨库直连）

| 库 | 归属 | 表（完整 DDL 见 make/技术设计文档 §6~§11） |
|---|---|---|
| yiliao_auth | auth | sys_user / sys_role / sys_user_role / sys_menu / sys_role_menu |
| yiliao_patient | patient | patient_archive / patient_risk_factor / patient_diagnosis |
| yiliao_nodule | nodule | nodule / nodule_snapshot / exam_report / lab_result |
| yiliao_followup | followup | followup_template / decision_rule / followup_plan / followup_task / followup_record / symptom_report |
| yiliao_notify | notification | message_record / education_article / questionnaire / questionnaire_answer |
| yiliao_ai | ai | ai_chat_session / ai_chat_message / knowledge_doc（向量在 PgVector） |
| yiliao_stats | statistics | 统计快照表（自建） |

- 跨服务取数：列表/详情走 Feign，状态同步走 MQ 事件本地落表；**禁止 A 服务直连 B 库、禁止跨库 JOIN**。
- `decision_rule` / `followup_template` 的指南初始数据以种子 SQL 维护在 `docker/init-sql/`。

## 5. Feign 契约（yiliao-api）

| 契约 | 提供方 | 主要方法 | 调用方 |
|---|---|---|---|
| `PatientApi` | patient | getArchive / pageArchives | followup、statistics、ai |
| `NoduleApi` | nodule | getTrend / latestSnapshot / reportSummary | followup、statistics、ai |
| `FollowupApi` | followup | nextFollowup / planTimeline | ai、statistics、patient |
| `AuthApi` | auth | getUserInfo / batchUserInfos | 各服务（显示操作者） |
| `AiApi` | ai | extractReport(rawText)→NoduleExtract | nodule |
| `FileApi` | file | presignUpload / presignDownload | nodule 等 |
| `NotifyApi` | notification | sendInternalMessage | 各服务即时通知 |

- 实现方式：提供方 `@RestController` 直接实现契约接口，编译期强约束契约同步。
- **契约路径强制约定（P2 实现修正）**：`@FeignClient` 的 `path` 属性只作用于客户端，不影响服务端映射。契约接口的方法映射必须写**绝对路径**（如 `@PostMapping("/api/followup/internal/plans/generate")`）；契约实现类**禁止**加类级 `@RequestMapping`（会与绝对路径双重前缀）。

## 6. MQ 主题契约

| 主题 | 生产 → 消费 | 用途 |
|---|---|---|
| `YILIAO_ARCHIVE_CREATED` | patient → followup | 建档完成兜底对账（幂等：已有进行中计划则跳过） |
| `YILIAO_EXTRACT_CONFIRMED` | nodule → followup | AI 抽取确认入库 → 生成/更新计划 |
| `YILIAO_PLAN_CREATED` | followup → notification | 计划生成 → 排程 T-7/T-3/T-1 提醒 |
| `YILIAO_REMIND_DUE` | followup→（定时消息）notification | 到点提醒；bizKey=`taskId:remindType` |
| `YILIAO_NODULE_PROGRESS` | nodule → followup、notification | 结节增大/实性成分 +≥2mm → 升级评估 + 预警 |
| `YILIAO_SYMPTOM_ALERT` | followup → notification | ePRO severity≥3 → 推送医生 |

- 命名 `YILIAO_{领域}_{事件}`；消费者继承 common-mq 幂等基类；失败重试 3 次 → 死信 + 告警人工。
- 提醒定时消息用 RocketMQ 5.x 任意定时（timer wheel）；若降级 4.x 客户端则按延迟级别表近似换算并在实现记录中注明。

## 7. 事务规则

- 单服务内一律本地事务（`@Transactional` 只标 service 层）。
- 跨服务强一致**仅一条链路**：建档（patient 创建档案 + nodule 快照 + followup 生成计划）用 **Seata AT**，TM 在 patient-service；失败整体回滚并提示人工重试。
- 其余跨服务状态变更一律 MQ 最终一致（本地写库 → 发事件 → 消费方落库，幂等对账）；**禁止滥用 Seata**。

## 8. 缓存与锁

- 两级缓存：Caffeine 本地（TTL 5min）+ Redis（TTL 30min），适用：随访模板、决策规则、字典、统计快照。
- key：`yiliao:{service}:{biz}:{id}`；规则/模板属低频变更，靠本地短 TTL 自然过期，不做跨实例主动失效（取舍：省一条广播，接受 5min 不一致）。
- 防穿透：规则/模板按 ID 查询走布隆过滤器（Redis）；空值缓存 60s。
- Redisson 锁：计划生成 `yiliao:lock:plan:{patientId}`（看门狗 30s），DB 唯一索引 `uk_patient_active` 兜底。

## 9. 配置约定

- Nacos：`namespace=dev/prod`，`group=YILIAO_GROUP`；共享 `yiliao-common.yaml` + `yiliao-{service}.yaml`；gateway 路由放 Nacos 动态刷新。
- 密钥只进 Nacos 加密配置或环境变量；仓库内一律占位符。
- 本地开发：`docker/docker-compose.yml` 起全部中间件，应用 IDE 启动。

## 禁止行为（全局）

1. 禁止服务间 Maven 直接依赖、跨库直连、跨库 JOIN。
2. 禁止硬编码随访规则（if-else 写间隔），规则只能存 `decision_rule`。
3. 禁止子 POM 自带版本号、禁止引入未经核验的新依赖。
4. 禁止对每条跨服务链路都上 Seata；除建档链路外一律 MQ 最终一致。
