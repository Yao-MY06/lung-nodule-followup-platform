# 全局公共规范（接口与横切层）

> 文档类型：全局规范　所属模块：全局　依赖文档：[specs/README.md]
> 版本：v1.0（2026-08-22）　阅读优先级：高
> 所有服务必须遵守；模块文档不再重复本文内容，仅写差异化约定。

## 1. 接口路径与 REST 约定

- 统一前缀 `/api/{服务名}`（如 `/api/followup/tasks`）；服务内资源用复数名词，动作用 HTTP 动词表达。
- 查询列表一律 GET + 分页参数（见 §3）；复杂查询条件用 Query String 传 DTO 字段。
- 患者端接口统一前缀 `/api/portal/**`：**服务端必须校验资源归属（仅本人数据）**，不依赖网关或前端隐藏（不变量，见 AGENTS.md）。
- 日期入参/出参格式：`yyyy-MM-dd HH:mm:ss`（日期为 `yyyy-MM-dd`），时区 GMT+8。

## 2. 统一返回体

```java
public record Result<T>(int code, String msg, T data) {
    public static <T> Result<T> ok(T data) { ... }          // code=0
    public static <T> Result<T> fail(ErrorCode ec) { ... }
}
```

- 成功 `code=0`；失败非 0。**禁止** Controller 绕过 `Result` 返回裸对象。
- 分页返回统一 `PageResult<T>`：`{records, total, page, size}`。

## 3. 分页与排序

- 入参继承 `PageQuery`（见【global/20-通用数据模型.md §5】）：`page`（默认 1）、`size`（默认 10，**上限 100**）、`sortBy`、`sortOrder(asc/desc)`。
- `sortBy` 必须白名单校验（只允许实体已有字段），防 SQL 注入。

## 4. 错误码规范

- 通用码：`0` 成功；`401` 未认证/Token 失效；`403` 无权限；`404` 资源不存在；`500` 系统异常。
- 业务码 5 位 = 服务段 2 位 + 序号 3 位：

| 服务段 | 服务 | 示例 |
|---|---|---|
| 10xxx | auth | 10001 用户名或密码错误 |
| 11xxx | gateway | 11001 触发限流 |
| 20xxx | patient | 20001 档案编号已存在 |
| 21xxx | nodule | 21001 快照缺少检查日期 |
| 22xxx | followup | 22001 该患者已有进行中计划 |
| 23xxx | notification | 23001 短信通道不可用 |
| 24xxx | ai | 24001 LLM 服务熔断降级 |
| 25xxx | statistics | — |
| 26xxx | file | 26001 预签名 URL 过期 |

- 业务错误码定义在各模块 `ErrorCode` 常量类中（值域遵循上表），新码必须同步登记到本文。

## 5. 认证与鉴权

- JWT：`Authorization: Bearer {accessToken}`；access 2h + refresh 7d；注销/改密后旧 Token 进 Redis 黑名单（key `yiliao:auth:blacklist:{jti}`，TTL=剩余有效期）。
- 网关统一校验 JWT + 黑名单，校验通过后**透传内部头** `X-User-Id`、`X-User-Roles` 给下游；内部服务信任网关（仅内网可达），但患者端数据权限仍由业务服务自查归属。
- 授权：RBAC，接口级用 `@PreAuthorize("hasAuthority('followup:task:list')")`，权限串 = `服务:资源:操作`。
- Feign 调用链由 `common-feign` 拦截器透传用户头与 traceId（详见【global/30-架构与工程约束.md §7】）。

## 6. 参数校验

- 入参 DTO 用 jakarta.validation 注解（`@NotNull/@NotBlank/@Size/@Pattern`），Controller 加 `@Valid`。
- 校验失败由 `common-web` 全局异常处理器统一转 `Result(code=400, msg=字段级错误信息)`。

## 7. 异常体系

- 业务异常统一抛 `BizException(ErrorCode)`（`common-core`）；全局异常处理器兜底：
  - `BizException` → 对应业务码
  - `MethodArgumentNotValidException` → 400 + 字段信息
  - `FeignException` → 按调用方语义转译（降级优先走 Sentinel fallback）
  - 兜底 `Exception` → 500，msg 不向客户端暴露堆栈（生产环境）
- **禁止** service 层吞异常（catch 后不打日志不抛出）。

## 8. 日志规范

- 格式：`%d [%X{traceId}] %-5p %c - %m%n`；traceId 由网关生成、SkyWalking 透传。
- 级别：入口/出口/Feign 调用/MQ 收发 = INFO；异常 = ERROR（含堆栈）；调试 = DEBUG（默认关闭）。
- **禁止**记录明文密码、完整身份证号/手机号、Token、LLM API Key；患者敏感字段打日志前脱敏。

## 9. 数据脱敏

- 手机号 `138****5678`；身份证保留前 3 后 4；姓名首字脱敏（患者列表场景，按需）。
- 实现：`@Sensitive(type)` 注解 + Jackson 序列化器（`common-web`），作用于 VO 字段，DB 存原文（身份证加密存储）。
- **AI 出网前过滤**：任何文本发送 LLM 前必须经过脱敏过滤器（去除姓名/证件号/手机号），详见【modules/ai.md §4】。

## 10. 接口文档

- 每服务集成 springdoc + Knife4j，分组名 = 服务名；网关聚合各服务文档。
- Controller 方法必须有 `@Operation(summary)`；DTO 字段 `@Schema(description)`。

## 禁止行为（全局）

1. 禁止绕过统一返回体、禁止 Controller 写业务逻辑、禁止 Mapper 互相调用。
2. 禁止新增错误码不登记、禁止 5 位码跨服务段使用。
3. 禁止日志/出参泄露敏感信息，禁止 AI 出网发送未脱敏文本。
