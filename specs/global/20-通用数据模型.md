> 版本：v1.0（2026-08-22）　阅读优先级：高

## 1. 实体基类 BaseEntity

```java
public abstract class BaseEntity {
    @TableId(type = IdType.AUTO) private Long id;
    @TableField(fill = FieldFill.INSERT)          private LocalDateTime createTime;
    @TableField(fill = FieldFill.INSERT_UPDATE)   private LocalDateTime updateTime;
    @TableField(fill = FieldFill.INSERT)          private Long createBy;
    @TableField(fill = FieldFill.INSERT_UPDATE)   private Long updateBy;
    @TableLogic private Integer deleted;   // 0正常 1已删除，逻辑删除
}
```

- 所有业务表实体继承 BaseEntity（`common-data` 提供自动填充与逻辑删除插件）；**禁止物理删除**业务数据。

## 2. 枚举编码总表

- 布尔语义字段统一 `0/1`；状态字段`0`保留为初始/未处理。

## 3. MQ 事件基类（common-mq）

```java
public record BaseEvent<T>(String eventId,     // UUID，消费幂等辅助
                           String eventType,   // 如 YILIAO_PLAN_CREATED
                           String bizKey,      // 业务幂等键，如 "taskId:REMIND_T7"
                           String source,      // 生产方服务名
                           LocalDateTime occurredAt,
                           T payload) {}
```

- 主题与事件清单详见【global/30-架构与工程约束.md §6】。
- 消费幂等规范：Redis `SETNX yiliao:mq:consumed:{eventType}:{bizKey}`（TTL 7 天）+ `message_record` 唯一键对账，双保险。

## 4. 字典策略（取舍声明）

- 稳定领域值（上表）用**代码内枚举**，不建字典表——毕设规模下减少一张表一层缓存。
- 可运营配置的内容（宣教分类、随访项目清单、话术）走各模块自己的配置表（如 `education_article.category`），不引入通用 `sys_dict`。
- 若后期需要运营侧改枚举文案，再引入字典表并迁移——记录在案即可。

## 5. 分页请求 PageQuery

```java
public class PageQuery {
    private Integer page = 1;
    @Max(100) private Integer size = 10;
    private String sortBy;       // 白名单校验
    private String sortOrder;    // asc / desc
}
```

## 6. 通用常量

- 缓存 key 前缀：`yiliao:{service}:{biz}:{id}`（完整策略见【global/30 §8】）。
- 分布式锁 key：`yiliao:lock:{biz}:{id}`。
- 内部透传头：`X-User-Id` / `X-User-Roles` / `X-Trace-Id`（详见【global/10 §5】）。

## 禁止行为

1. 禁止模块内自定义与上表语义重复的枚举或常量类。
2. 禁止业务表不加 `deleted` 逻辑删除、禁止代码物理 DELETE 业务表。
