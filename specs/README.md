# specs/ —— 分层设计文档体系（实现事实源）

> 文档类型：文档地图　　版本：v1.0（2026-08-22）
> **本目录是实现阶段的事实源**。`make/` 下三份大文档是需求调研与论文素材快照；两者冲突时以 `specs/` 为准，并把差异回写 `make/`。

## 文档分层与阅读顺序

```
AGENTS.md（项目上下文）
  └─ specs/README.md（本文件）
       ├─ global/  全局公共文档（所有模块共用，开工必读）
       │    ├─ 10-全局公共规范.md      接口/返回体/错误码/鉴权/日志/脱敏
       │    ├─ 20-通用数据模型.md      公共枚举/BaseEntity/事件基类/分页
       │    └─ 30-架构与工程约束.md    版本基线/模块依赖/分库/契约/事务/缓存/幂等
       ├─ modules/ 模块专属文档（只写本模块独有内容）
       │    ├─ gateway.md  auth.md  patient.md  nodule.md  followup.md
       │    └─ notification.md  ai.md  statistics.md  file.md   （yiliao-ui 待补）
       └─ flows/  跨模块流程文档（多服务协同链路）
            ├─ F1-建档与计划生成.md
            ├─ F2-提醒与失访闭环.md
            ├─ F3-复查对比与升级.md
            └─ F4-AI助手.md
```

**AI 阅读规则**：先读 `global/` 三份建立基线 → 只加载目标模块的 `modules/{模块}.md` → 涉及跨服务链路时再加载对应 `flows/` 文档。禁止跳过全局文档直接写代码。

## 编写规则（所有 specs 文档必须遵守）

1. **固定元信息头**：每份文档开头必须含 `文档类型 / 所属模块 / 依赖文档 / 版本 / 阅读优先级` 五项。
2. **禁止冗余复制，用引用**：通用规则一律写 `详见【global/10-全局公共规范.md §N】`，不在模块文档重复；模块文档只写本模块独有内容。
3. **固定结构**：模块文档统一为 `职责边界 → 数据模型 → 接口定义 → 业务规则 → 异常场景 → 禁止行为 → 依赖声明 → 最小调用示例`。
4. **单文档 ≤ 300 行**：超限必须拆子文档，顶层保留入口。
5. **变更记录**：文档末尾保留变更表（版本/日期/变更/原因），防止 AI 读到过时规则。

### 模块文档模板

```markdown
# {模块名}（{服务名}/{端口}）

> 文档类型：业务模块文档　所属模块：{service}　依赖文档：[global/10, global/20, global/30]
> 版本：v1.0（YYYY-MM-DD）　阅读优先级：高|中

## 1. 职责边界与能力清单      # 做什么/不做什么（一句话级别）
## 2. 数据模型                # 私有表清单+关键字段与不变量；完整 DDL 引用 make/技术设计文档 §N
## 3. 接口定义                # 本服务 REST + 对外 Feign 契约
## 4. 业务规则                # 本模块独有的规则、算法、状态机
## 5. 异常场景                # 关键失败路径与处理
## 6. 禁止行为                # 本模块绝对不能做的事（约束 AI 越界）
## 7. 依赖声明                # 依赖的公共能力/上游下游（Feign/MQ/DB/中间件）
## 8. 最小调用示例            # 一个 curl 或 Feign 调用片段

## 变更记录
```

## 落地顺序（P0→P5）

| 阶段 | 交付 | 验收点 |
|---|---|---|
| P0 工程底座 | parent + 6 个 common + api 骨架 + docker-compose | `mvn install` 全绿；中间件可访问；版本锁定 |
| P1 接入层 | gateway + auth | 经网关登录鉴权全链路走通 |
| P2 核心域 | patient → nodule → followup（规则引擎+工作台） | 建档自动出计划；改规则表即时生效 |
| P3 消息闭环 | notification + XXL-Job 扫描 | 到点提醒；重复投递不重发 |
| P4 AI 能力 | ai-service + Seata + file | 报告→抽取→确认→排期主线 |
| P5 呈现治理 | statistics + Sentinel 熔断 + JMeter 压测 | 压测对比图、熔断演示 |
