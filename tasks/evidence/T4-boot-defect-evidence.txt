五、Spring 行为判定
  @Component 组件扫描 + 类内声明 2 个构造器（无无参构造器、无 @Autowired 标注）→
  AutowiredAnnotationBeanPostProcessor 无法确定候选构造器 → 走 instantiateBean() 默认
  无参构造路径 → NoSuchMethodException。确定性缺陷，与 LLM Key/数据源/环境变量无关
  （失败发生在 LLM 连通性验证之前的上下文装配阶段）。

六、为何 mvn test 全绿未拦截
  yiliao-ai 全部测试为纯 Mockito 单测（无 @SpringBootTest/@MockBean）：
  - ChatServiceTest.java:42  @Mock private PatientTools patientTools;
  - PatientToolsTest.java:50/63/74/84/94  直接 new PatientTools(followupApi, noduleApi)
  无任何用例装载 Spring 上下文 → 上下文装配失败对测试套件不可见
  （与 R1 缺陷"单测未覆盖流式集成路径"同模式：测试盲区，非测试失败）。

七、修复方向（供主线决策，本次未改动任何代码）
  方案A：public 双参构造器加 @Autowired（最小改动，保留 @Component 基座 bean）
  方案B：去掉 @Component，ChatService 注入 FollowupApi/NoduleApi 自行
         new PatientTools(a,b).forPatient(id)（每次请求新建，语义最贴合现有 forPatient 设计）
  方案C：只保留 4 参私有构造器 + 静态工厂，消除多构造器歧义
  建议随修：补一个上下文装配冒烟测试（@SpringBootTest 或 ApplicationContextRunner），
  把"启动失败"纳入 mvn test 可见范围。
