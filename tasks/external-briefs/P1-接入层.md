## 1. 目标与边界

**目标**：登录鉴权全链路骨架，满足验收：
- `mvn install` 全绿（11 个模块：P0 的 9 个 + yiliao-gateway + yiliao-auth）
- JWT 签发/解析/过期/黑名单单测通过（common-security 新增 7 用例）
- 登录成功/密码错/锁定/停用单测通过（auth 5 用例）；网关过滤器放行与拦截单测通过（gateway 7 用例）
- `yiliao_auth` 库 DDL + 种子可重复执行（幂等）

**不在范围**：菜单树接口、用户 CRUD 管理（P1b）；Sentinel 限流（P5）；患者端数据权限（P2）；中间件运行链路验证（docker 仅配置校验）。

**本阶段新增/修改**：
- 新增：`yiliao-gateway/**`、`yiliao-auth/**`、`yiliao-api` auth 包、`docker/init-sql/yiliao_auth.sql`、common-security jwt 包（2 类 + 1 测试）
- 修改：根 `pom.xml`（modules 追加 2 个）

## 2. 硬约束（违反即返工）

1. P0 全部硬约束继续有效（版本三元组锁根 POM、子 POM 禁写版本、禁 Lombok、common 间仅依赖 core）。
2. **gateway 是 WebFlux 栈，禁止依赖 yiliao-common-web**（servlet 栈冲突）；gateway 只用 common-core + common-security。
3. **Feign 契约铁律**：契约方法写绝对路径；服务端实现类 `implements` 契约接口，**禁止类级 `@RequestMapping`**（实现方法不带路径注解，直接 `@Override`）。
4. JWT secret 为 **HS256**：UTF-8 字节数必须 ≥32，否则 `JwtTokenService` 构造抛 `IllegalStateException`。auth 与 gateway 的 secret/issuer 配置必须逐字一致。
5. 密码只存 BCrypt 哈希（strength=10）；任何接口返回体禁止包含 password 字段；登录失败提示统一文案防账号枚举。
6. Redis key 格式跨服务一致：auth 写入黑名单，gateway 读取——格式 `yiliao:auth:blacklist:{jti}`，不得各自定义。

## 3. 已知陷阱（先记再写）

1. P0 的 4 条陷阱全部继续有效（JDK25 surefire argLine、MP insert 重载、record 访问器 `code()/data()`、Boot3 AutoConfiguration.imports）。
2. **WebFlux 网关测试**用 `reactor-test` 的 `StepVerifier` 或直接调用过滤器方法；不要引 spring-boot-starter-web 到 gateway。
3. **jjwt 0.12.6 API**：`Jwts.parser().verifyWith(key).requireIssuer(...).build().parseSignedClaims(token)`；`Keys.hmacShaKeyFor(bytes)`。0.12.x 已删除 `parserBuilder()` 旧 API。
4. 网关过滤器中 Redis 调用失败要 **fail-open**（放行 + error 日志），可用性优先——医疗系统鉴权不能因 Redis 抖动全员 401。
5. `@ConfigurationProperties` record 需要 `@EnableConfigurationProperties` 或 `@ConfigurationPropertiesScan` 显式装配。

### 步骤 2：common-security 新增 JWT 实现（jwt 包，`com.yiliao.common.security.jwt`）

**2.1 `JwtProperties`**（全文即规格）：
```java
@ConfigurationProperties(prefix = "yiliao.jwt")
public record JwtProperties(
        String secret,
        String issuer,
        long accessTtlSeconds,
        long refreshTtlSeconds
) {
}
```
类 javadoc 注明：auth 与 gateway 必须配置相同 secret 与 issuer；生产走 Nacos/环境变量覆盖。

**2.2 `JwtTokenService`**：
- 常量：`public static final String TYPE_ACCESS = "access";`、`TYPE_REFRESH = "refresh"`
- 构造器 `JwtTokenService(JwtProperties properties)`：secret 为 null 或 UTF-8 字节数 < 32 → 抛 `IllegalStateException("yiliao.jwt.secret 必须至少 32 字节（HS256 要求）")`；`key = Keys.hmacShaKeyFor(secret.getBytes(UTF_8))`
- `public TokenPayload issueAccessToken(Long userId, String username, Integer userType, List<String> roles)` / `issueRefreshToken(...)` 同参：内部 `issue(type)`，`jti = UUID.randomUUID().toString()`，claims：`id(jti)`、`subject(String.valueOf(userId))`、`issuer`、`issuedAt(now)`、`expiration(now + ttl*1000)`（access 用 `accessTtlSeconds`，refresh 用 `refreshTtlSeconds`）、`claim("uname", username)`、`claim("utype", userType)`、`claim("roles", String.join(",", roles))`、`claim("type", type)`，HS256 签名
- `public TokenPayload parse(String token)`：`Jwts.parser().verifyWith(key).requireIssuer(issuer).build().parseSignedClaims(token)`；捕获 `JwtException | IllegalArgumentException` → 抛 `BizException(CommonErrorCode.UNAUTHORIZED)`
- `public TokenPayload parse(String token, String expectedType)`：先 parse；payload 的 tokenType ≠ expectedType → 抛 `BizException(CommonErrorCode.UNAUTHORIZED)`（防 access Token 当 refresh 用）
- `public long remainingSeconds(TokenPayload payload)`：`(expiresAt - now)/1000`，`Math.max(0, ...)`
- 内部 record（逐字）：
```java
/**
 * Token 载荷。token 字段仅签发方向填入，解析结果为 null。
 */
public record TokenPayload(
        String jti,
        Long userId,
        String username,
        Integer userType,
        List<String> roles,
        String tokenType,
        String token,
        Date expiresAt
) {
}
```
- `toPayload(Claims)`：roles claim 按逗号 split，空 → `List.of()`；token 字段 null

**2.3 测试 `JwtTokenServiceTest`**（纯 JUnit + 自造 JwtProperties，secret 用 32+ 字节的固定测试值），7 个用例：
- `accessTokenRoundTripKeepsClaims` — 签发后解析回 userId/username/userType/roles/tokenType 一致且未过期
- `jtiIsUniquePerIssue` — 两次签发 token 与 jti 均不同
- `expiredTokenRejectedAs401` — ttl 设 1 秒并 sleep 过后 parse 抛 UNAUTHORIZED（或构造过期 token）
- `wrongSignatureRejected` — 另一 secret 构造的服务解析抛 BizException
- `accessTokenRejectedWhereRefreshExpected` — access Token 按 TYPE_REFRESH 解析抛 401
- `secretTooShortRejectedAtConstruction` — secret="short" 构造抛 IllegalStateException
- `remainingSecondsNeverNegative` — 剩余秒数 ≥ 0

- `YiliaoAuthApplication`：`@SpringBootApplication @ConfigurationPropertiesScan @EnableFeignClients(basePackages = "com.yiliao.api")`
- `config.AuthBeanConfig`（`@Configuration @EnableConfigurationProperties(JwtProperties.class)`）：
  - `@Bean JwtTokenService jwtTokenService(JwtProperties p)`
  - `@Bean BCryptPasswordEncoder passwordEncoder()` → `new BCryptPasswordEncoder(10)`
  - `@Bean UserContextProvider userContextProvider()` → lambda：`RequestContextHolder` 取当前请求头 `X-User-Id`（`YiliaoConstants.HEADER_USER_ID`），非空返回 `Long.valueOf`，否则 null

- `mapper.SysUserMapper`：`@Mapper extends BaseMapper<SysUser>`
- `mapper.SysRoleMapper`：`@Mapper extends BaseMapper<SysRole>` +

- `dto.LoginRequest`：record `@NotBlank(message="用户名不能为空") String username, @NotBlank(message="密码不能为空") String password`
- `dto.RefreshRequest`：record `@NotBlank(message="refreshToken 不能为空") String refreshToken`
- `dto.LoginResponse`：record `String accessToken, String refreshToken, String tokenType, long expiresInSeconds, Long userId, String realName, Integer userType, List<String> roles`
- `error.AuthErrorCode`：枚举 implements ErrorCode（模式同 CommonErrorCode，含 `withMsg` 内部 record）：
  - `BAD_CREDENTIALS(10001, "用户名或密码错误")`
  - `ACCOUNT_LOCKED(10002, "登录失败次数过多，账号已临时锁定")`
  - `ACCOUNT_DISABLED(10003, "账号已停用")`
  - `TOKEN_INVALID(10004, "登录凭证无效或已过期")`
  - `REFRESH_INVALID(10005, "刷新凭证无效或已过期")`
- `service.TokenBlacklistService`（`@Service`）：
  - `static String key(String jti)` → `YiliaoConstants.TOKEN_BLACKLIST_PREFIX + jti`
  - `void blacklist(JwtTokenService.TokenPayload payload)`：`remaining = payload.expiresAt().getTime() - now`；`remaining > 0` 时 `opsForValue().set(key, "1", Duration.ofMillis(remaining))`（TTL=剩余有效期）
  - `boolean isBlacklisted(String jti)`：`Boolean.TRUE.equals(redisTemplate.hasKey(key))`
- `service.AuthService`（`@Service`；javadoc：失败统一 10001 防枚举；连续失败 5 次锁定 10 分钟；停用账号拒绝登录）：
  - 常量：`static final int MAX_FAIL_COUNT = 5;`、`static final Duration LOCK_DURATION = Duration.ofMinutes(10);`
  - `static String failKey(String username)` → `YiliaoConstants.CACHE_PREFIX + "auth:fail:" + username`（即 `yiliao:auth:fail:{username}`）
  - `LoginResponse login(LoginRequest)`：① `checkLocked(failKey)`；② 按 username 查用户；③ 用户不存在 **或** `!passwordEncoder.matches` → `recordFailure` + 抛 `BAD_CREDENTIALS`（两者同文案防枚举）；④ `status != 1` → 抛 `ACCOUNT_DISABLED`；⑤ 成功：`redisTemplate.delete(failKey)`、`selectRoleCodes` 加载角色、`buildResponse`
  - `LoginResponse refresh(String refreshToken)`：`parse(token, TYPE_REFRESH)` 失败 → `REFRESH_INVALID`；jti 在黑名单 → `REFRESH_INVALID`；用户不存在/停用 → `ACCOUNT_DISABLED`；旧 refresh 拉黑后**轮换**签发新 Token 对
  - `void logout(String accessToken, String refreshToken)`：两 token 分别"parse + 拉黑"，parse 失败静默忽略（幂等）
  - `LoginResponse issueForUser(Long userId)`：查用户（null 抛 `TOKEN_INVALID`）后签发
  - `buildResponse`：签发 access+refresh；`expiresInSeconds = (access.expiresAt - now)/1000`；tokenType="Bearer"
  - `checkLocked`：计数 `>= MAX_FAIL_COUNT` 抛 `ACCOUNT_LOCKED`
  - `recordFailure`：`increment(failKey)`，`count == 1` 时 `expire(failKey, LOCK_DURATION)`；`log.warn("登录失败 failKey={} count={}", ...)`
- `controller.AuthController`（`@RestController @RequestMapping("/api/auth")`，Knife4j `@Operation`）：
  - `POST /api/auth/login`，`@Valid @RequestBody LoginRequest` → `Result<LoginResponse>`
  - `POST /api/auth/refresh`，`@Valid @RequestBody RefreshRequest` → `Result<LoginResponse>`
  - `POST /api/auth/logout`，`@RequestHeader(value="Authorization", required=false)` + `@RequestBody(required=false) RefreshRequest` → `Result<Void>`；切出 Bearer accessToken 调 `logout`
  - `POST /api/auth/me`，`@RequestHeader Authorization(required=false)` + `@RequestHeader(HEADER_USER_ID, required=false)` → `Result<LoginResponse>`；userId 优先取 `X-User-Id` 头，否则 parse token 取 userId，都无抛 `TOKEN_INVALID`
- `feign.AuthApiController`：`@RestController implements AuthApi`（**无类级 @RequestMapping**；方法 `@Override`，路径由契约接口携带）：
  - `getUserInfo(id)`：`selectById`，null → `Result.ok(null)`，否则转 DTO
  - `batchUserInfos(ids)`：空 → `Result.ok(List.of())`；否则 `in(id, ids)` 批量查
  - `toDTO`：`new UserInfoDTO(user.getId(), user.getRealName(), user.getUserType(), roleMapper.selectRoleCodes(user.getId()))`

**3.4 测试 `AuthServiceTest`**（`@ExtendWith(MockitoExtension.class)`，mock userMapper/roleMapper/redisTemplate+valueOps/tokenBlacklistService/JwtTokenService），5 个用例：

- `filter.AuthGlobalFilter`（`implements GlobalFilter, Ordered`，`getOrder()` 返回 `-100`）：
  - 常量（逐字）：
```java
private static final String[] WHITELIST = {
        "/api/auth/login", "/api/auth/refresh",
        "/doc.html", "/webjars/**", "/v3/api-docs/**", "/favicon.ico"
};
private static final String INTERNAL_PATTERN = "/api/*/internal/**";
```
  - 处理顺序（`AntPathMatcher` 匹配 path）：
    1. 命中 `INTERNAL_PATTERN` → 直接 404 `Result.fail(CommonErrorCode.NOT_FOUND)`（internal 路径禁止外部访问）
    2. 命中 WHITELIST → 注入 TraceId 后放行
    3. 无 `Authorization: Bearer ` 前缀（或长度 ≤7）→ 401 `UNAUTHORIZED`
    4. `jwtTokenService.parse(token, TYPE_ACCESS)` 抛 BizException → 401
    5. 黑名单：`redisTemplate.hasKey("yiliao:auth:blacklist:" + jti)`；**`onErrorResume` fail-open**（`log.error` 后返回 `Mono.just(false)`）；命中 → 401
    6. 通过：mutate 请求注入头 `X-User-Id`（`String.valueOf(payload.userId())`）、`X-User-Roles`（`String.join(",", payload.roles())`）后放行
  - TraceId：读 `X-Trace-Id` 头，空则 `UUID.randomUUID().toString()`，注入该头（白名单请求也注入）
  - 写 401/404 响应：`ServerResponse` 状态码 + `APPLICATION_JSON`，ObjectMapper 序列化 Result；序列化异常回退 body `{"code":500,"msg":"系统繁忙"}`
  - 构造注入：`JwtTokenService`、`ReactiveStringRedisTemplate`
- 测试 `AuthGlobalFilterTest`（构造真实 JwtTokenService，secret 用固定测试值 `unit-test-secret-key-0123456789abcdef0123456789`，mock `ReactiveStringRedisTemplate`），7 个用例：
  - `loginWhitelistedWithoutToken` — POST /api/auth/login 无 Token 放行且注入 X-Trace-Id
  - `internalPathGets404` — GET /api/auth/internal/users/1 → 404 且不进 chain
  - `missingTokenGets401` — 业务路径无 Token → 401
  - `garbageTokenGets401` — `Bearer not-a-jwt` → 401
  - `blacklistedTokenGets401` — hasKey 返回 true 时有效 Token 也 401
  - `validTokenRelaysUserHeaders` — hasKey=false 时放行，断言 X-User-Id="7"、X-User-Roles="DOCTOR"、X-Trace-Id 非空
  - `redisFailureFailsOpen` — hasKey 返回 `Mono.error` 时 fail-open 放行
