> 用途：交给另一个模型执行 P3（yiliao-notification + followup 提醒派发/逾期失访 + 幂等三保险 + XXL-Job）。
> ⚠️ **前置**：必须在已完成 P0 + P1 + P2 执行书的**同一目录**内继续（14 模块已构建通过）。

## 1. 目标与边界

**目标**：提醒消息闭环 + 幂等可靠性（论文深度点），满足验收：
- `mvn install` 全绿（15 个模块：P2 的 14 个 + yiliao-notification）
- 幂等单测：重复 bizKey 首次发送、第二次丢弃
- RemindPlanner 单测：T-7/T-3/T-1 日期计算、已过点不补、对账补投逻辑
- 逾期分类单测：>7 天逾期、>30 天失访、当日不误伤

**不在范围**：宣教/问卷 CRUD（P3b，只建表）；短信厂商真实对接（接口化 stub）；Seata；患者端 H5。

**本阶段新增/修改**：
- 新增：`yiliao-notification/**`、followup 的 remind/scan/job/mq 包、`docker/init-sql/yiliao_notify.sql`、yiliao-api notify 包
- 修改：根 pom（modules +1）、gateway 路由（+notify）

## 2. 硬约束（违反即返工）

1. P0/P1/P2 全部硬约束继续有效。
2. **消息幂等三保险**（关键不变量，重复投递不得重复发短信）：
   - ① Redis SETNX：key = `yiliao:mq:consumed:{eventType}:{bizKey}`，TTL 7 天（`MQ_CONSUMED_TTL_DAYS`）
   - ② `message_record.biz_key` 数据库唯一键兜底（并发下另一实例已处理时 `DuplicateKeyException` 静默）
   - ③ 渠道发送只发一次；处理失败（非幂等丢弃）必须 `release()` 释放 Redis 标记后 rethrow 触发 MQ 重试
3. **bizKey 契约**：提醒消息 `bizKey = {taskId}:REMIND_T{7|3|1}`（remindType 1→7、2→3、3→1）；计划事件 `bizKey = plan:{planId}`。跨服务必须逐字一致。
4. **实现决策（前置声明）**：rocketmq-spring 2.3.1 的 delayLevel 上限 2 小时，无法表达天级定时——生产端采用**扫描派发**（XXL-Job 每分钟扫到期提醒点 + 每小时对账补投），不做 MQ 延迟消息。javadoc 中保留 `remind.mode=mq-delay` 升级预留说明（无对应配置读取代码）。
5. 消费端异常向上抛出触发 MQ 重试（3 次进死信，broker 端配置）；幂等丢弃**不**抛异常。
6. 逾期/失访判定为**严格大于**：>7 天逾期、>30 天失访；恰好 7 天 KEEP（不误伤）。
7. XXL-Job 分片：2.4.1 用 `XxlJobHelper.getShardIndex()/getShardTotal()`（ShardingUtil 已删除，禁止引用）；分片按 `patientId % shardTotal == shardIndex`。

## 3. 已知陷阱（先记再写）

1. P0~P2 全部陷阱继续有效。
2. **RocketMQ 监听器**：`@RocketMQMessageListener(topic = Topics.XXX, consumerGroup = "...")` + `implements RocketMQListener<BaseEvent<Payload>>`；topic 必须用 common-mq 的 `Topics` 常量，禁止字符串硬编码。
3. **XXL-Job 条件装配**：`@ConditionalOnProperty(name="yiliao.xxl-job.enabled", havingValue="true")`，默认 false——无 xxl-job-admin 时服务照常启动，测试不受影响。
4. `RocketMQTemplate.syncSend(topic, MessageBuilder.withPayload(event).setHeader("KEYS", bizKey).build())`；通知性事件（PLAN_CREATED）发送失败仅 `log.warn` 不回滚业务。
5. `@RocketMQMessageListener` 所在服务必须配 `rocketmq.name-server`；消费端不需要 producer group。

**1.1 `mq/idempotent/IdempotentChecker`**（`@Component`，注入 `StringRedisTemplate`）：
```java
/** MQ 消费幂等（specs/global/30 §6）：SETNX 第一道保险，key = yiliao:mq:consumed:{eventType}:{bizKey}，TTL 7 天。 */
public boolean tryConsume(String eventType, String bizKey) {
    String key = YiliaoConstants.MQ_CONSUMED_PREFIX + eventType + ":" + bizKey;
    Boolean first = redisTemplate.opsForValue()
            .setIfAbsent(key, "1", Duration.ofDays(YiliaoConstants.MQ_CONSUMED_TTL_DAYS));
    return Boolean.TRUE.equals(first);
}

public void release(String eventType, String bizKey) {
    redisTemplate.delete(YiliaoConstants.MQ_CONSUMED_PREFIX + eventType + ":" + bizKey);
}
```

**1.2 `mq/config/YiliaoMqAutoConfiguration`**（`@AutoConfiguration`）：`@Bean IdempotentChecker`（ObjectProvider 或构造注入 StringRedisTemplate）；注册文件 `src/main/resources/META-INF/spring/org.springframework.boot.autoconfigure.AutoConfiguration.imports` 一行 `com.yiliao.common.mq.config.YiliaoMqAutoConfiguration`。
