# 第一部分　总体设计

## 1. 系统定位

面向医院呼吸科/胸外科/肿瘤科的肺结节与肺癌患者全周期管理平台，覆盖"建档 → 风险评估 → 随访计划自动生成 → 智能提醒 → 复查对比 → 预警干预"闭环，并以 AI 能力（报告结构化抽取、指南知识库问答、智能助手）提升录入效率与患者服务质量。

## 3. 总体架构

```
                        ┌─────────────┐
        管理端 Web ────▶│             │
        患者端 H5 ─────▶│   Gateway   │── 鉴权/限流/路由
                        └──────┬──────┘
        ┌──────────────┬───────┼───────────┬──────────────┐
        ▼              ▼       ▼           ▼              ▼
  auth-service   patient-   nodule-    followup-     notification-
  (认证/RBAC)    service    service    service       service
                 (档案)     (结节/检查) (计划/执行)    (消息推送)
                                    │
        ┌───────────────────────────┼───────────────────┐
        ▼                           ▼                   ▼
   ai-service                 statistics-           file-service
   (LLM/RAG/抽取/Agent)        service(驾驶舱)        (MinIO 附件)

  基础设施：Nacos | MySQL | Redis | RocketMQ | XXL-Job | MinIO | Sentinel | SkyWalking
```

## 4. 服务划分与职责

| 服务 | 端口 | 核心职责 | 依赖中间件 |
|---|---|---|---|
| gateway | 8080 | 路由、JWT 校验、限流、CORS | Sentinel、Redis |
| auth-service | 8081 | 登录、Token 签发/刷新/注销、用户/角色/菜单 | MySQL、Redis |
| patient-service | 8082 | 患者档案、危险因素、诊断/分期、医生-患者绑定 | MySQL、Redis |
| nodule-service | 8083 | 结节登记、复查快照、纵向对比、检查检验/病理报告 | MySQL、MinIO |
| followup-service | 8084 | 随访规则引擎、计划生成、任务调度、随访记录、失访管理 | MySQL、Redis、RocketMQ、XXL-Job |
| notification-service | 8085 | 站内信、短信、模板消息；延迟消息消费 | RocketMQ、Redis |
| ai-service | 8086 | 报告解读、RAG 问答、报告结构化抽取、Tool Calling 助手 | PgVector、Redis、LLM API |
| statistics-service | 8087 | 随访完成率/失访率/结节分布等统计驾驶舱 | MySQL |
| file-service | 8088 | 附件上传下载、脱敏预览 | MinIO |

**服务间通信**：同步查询走 OpenFeign（带 Sentinel 降级）；状态变更类事件走 RocketMQ（最终一致）。

## 5. 核心业务流程时序

### 5.1 建档 + AI 抽取 + 自动生成随访计划（Seata 分布式事务）

```
医生端            nodule/ai              followup
  │  粘贴CT报告原文   │                    │
  ├─▶ ai-service /report/extract ──▶ LLM 结构化输出(JSON)─┐
  │◀──── 结节字段草稿(人工确认)                            │
  │  确认提交建档                                         │
  ├─▶ patient-service 创建档案(TM)  ──Seata AT──▶         │
  │       ├─▶ nodule-service 写入结节快照                 │
  │       └─▶ followup-service 规则引擎匹配模板           │
  │                     ├─ decision_rule 表驱动匹配        │
  │                     ├─ Redisson 锁防重复生成           │
  │                     └─ 生成 followup_plan + 未来任务   │
  │  提交成功                                             │
  └─▶ followup-service 投递 MQ 事件 PLAN_CREATED
                        └─▶ notification-service 排程提醒(延迟消息)
```

### 5.2 复查提醒（延迟消息 + 幂等）

```
计划生成 → 计算 T-7/T-3/T-1 三个提醒点
        → 每个提醒点投递 RocketMQ 延迟消息(msgKey=taskId+remindType)
        → 到期由 notification-service 消费
              ├─ 幂等校验(Redis SETNX msgKey，已发则丢弃)
              ├─ 发送站内信+短信，写 message_record
              └─ 消费失败 → 重试 3 次 → 死信队列 → 告警人工介入
```

### 5.3 逾期与失访（XXL-Job）

```
每日 02:00 分片广播扫描 followup_task：
  状态=待完成 且 计划日期 < today-7  → 标记"逾期"，推送主管医生
  状态=逾期 且 计划日期 < today-30 → 标记"疑似失访"，进入失访名单
  多次提醒无效(≥3次) → 随访专员人工电话追踪，结果写 followup_record
```

### 5.4 复查结果录入 → 结节对比 → 计划自适应

```
录入复查(新快照) → 与上次快照对比(最大径/实性成分/密度)
  ├─ 增大或实性成分增加 ≥2mm → 规则引擎升级随访级别
  │     → 重算后续任务间隔 → 推送预警给主管医生
  ├─ 稳定 → 按模板生成下一期任务
  └─ 高度疑恶性 → 转 MDT 流程(可选) / 标记转治疗
```

### 5.5 AI 助手（Tool Calling）

```
患者："我下次什么时候复查？最近有点咳嗽要紧吗？"
  → ai-service：LLM 决策调用工具
       ├─ queryNextFollowup(patientId)  → followup-service 真实数据
       └─ reportSymptom(patientId, "咳嗽", 程度) → 症状上报入库+阈值判断
  → LLM 整合工具结果 + RAG 召回的指南段落
  → SSE 流式输出回答(附指南出处) → 症状超阈值则推送预警给医生
```

# 第二部分　数据库设计（核心表）

> 命名规范：小写下划线、服务前缀；所有表含 `create_time/update_time/create_by/update_by/deleted`（逻辑删除）。以下为核心表 DDL（MySQL 8）。

## 6. 用户与权限（auth-service）

```sql
CREATE TABLE sys_user (
  id            BIGINT PRIMARY KEY AUTO_INCREMENT,
  username      VARCHAR(32)  NOT NULL UNIQUE COMMENT '登录名',
  password      VARCHAR(100) NOT NULL COMMENT 'BCrypt加密',
  real_name     VARCHAR(32)  NOT NULL,
  phone         VARCHAR(20),
  user_type     TINYINT NOT NULL COMMENT '1管理员 2医生 3随访专员 4患者',
  dept          VARCHAR(64),
  status        TINYINT DEFAULT 1 COMMENT '1正常 0停用',
  create_time   DATETIME DEFAULT CURRENT_TIMESTAMP,
  update_time   DATETIME DEFAULT CURRENT_TIMESTAMP ON UPDATE CURRENT_TIMESTAMP,
  deleted       TINYINT DEFAULT 0
);

CREATE TABLE sys_role (
  id BIGINT PRIMARY KEY AUTO_INCREMENT,
  role_code VARCHAR(32) NOT NULL UNIQUE COMMENT 'ADMIN/DOCTOR/NURSE/PATIENT',
  role_name VARCHAR(32) NOT NULL
);

CREATE TABLE sys_user_role (
  user_id BIGINT NOT NULL, role_id BIGINT NOT NULL,
  PRIMARY KEY(user_id, role_id)
);

CREATE TABLE sys_menu (          -- 菜单/按钮权限
  id BIGINT PRIMARY KEY AUTO_INCREMENT,
  parent_id BIGINT DEFAULT 0,
  menu_name VARCHAR(64), path VARCHAR(128),
  perms VARCHAR(64) COMMENT '如 followup:task:list',
  menu_type TINYINT COMMENT '1目录 2菜单 3按钮',
  sort INT DEFAULT 0
);

CREATE TABLE sys_role_menu (
  role_id BIGINT NOT NULL, menu_id BIGINT NOT NULL,
  PRIMARY KEY(role_id, menu_id)
);
```

# 第三部分　接口设计（核心 REST API）

> 约定：统一前缀 `/api/{服务名}`；统一返回体 `Result<T>{code,msg,data}`；分页用 MyBatis-Plus `Page`；鉴权走 Gateway + JWT（患者端接口仅可访问本人数据，服务端做数据权限校验）。以下按服务列核心接口。

## 12. auth-service

| 方法 | 路径 | 说明 |
|---|---|---|
| POST | /api/auth/login | 登录，返回 accessToken+refreshToken |
| POST | /api/auth/refresh | 刷新 Token |
| POST | /api/auth/logout | 注销（Token 入 Redis 黑名单） |
| GET | /api/auth/menus | 当前用户菜单/权限树 |
| GET/POST/PUT/DELETE | /api/auth/users | 用户 CRUD（管理员） |

## 13. patient-service

| 方法 | 路径 | 说明 |
|---|---|---|
| POST | /api/patient/archives | 建档（触发 Seata 全局事务） |
| GET | /api/patient/archives | 分页查询（按医生/阶段标签/关键字） |
| GET | /api/patient/archives/{id} | 档案详情（含危险因素、诊断） |

# 第四部分　AI 模块详细设计

## 18. 报告结构化抽取（A3）

- **输入**：`exam_report.raw_text`（CT 报告原文，提交前脱敏）。
- **实现**：Spring AI `ChatClient` + 结构化输出（BeanOutputConverter 绑定 Java DTO）。
- **输出 DTO**：

```java
public record NoduleExtract(
    String location,            // 位置
    String noduleType,          // SOLID / PART_SOLID / PURE_GG
    BigDecimal maxDiameterMm,   // 最大径
    BigDecimal solidDiameterMm, // 实性成分径
    Integer count,              // 数量
    List<String> signs,         // 恶性征象
    String impression           // 影像结论
) {}
```

- **Prompt 要点**：角色=放射科结构化助手；仅抽取原文存在的信息，缺失字段返回 null 禁止臆造；输出严格 JSON。
- **流程**：抽取 → 前端展示草稿 → 医生人工确认 → 写入 nodule/snapshot → 触发规则匹配。**AI 只起草、人确认，是医疗系统的安全底线。**

## 19. RAG 知识库问答（A2）

- **文档处理**：指南 PDF/MD 按章节语义切分（chunk 500~800 字，重叠 100 字），保留"文档名+章节"元数据。
- **检索**：混合检索 = BGE Embedding 向量检索（PgVector）+ 关键词检索（BM25），RRF 融合取 Top 8 → bge-reranker 精排取 Top 3 → 拼入 Prompt。
- **降级**：Rerank 服务不可用时回退原始排序；向量库不可用时回答"知识库暂不可用"而非自由发挥。
- **输出约束**：回答末尾必须附引用出处（文档名+章节）；与诊疗决策相关的内容追加"仅供参考，以主治医生意见为准"。
- **评测**：构建 40 题随访知识评测集，对比"纯向量 / 混合 / 混合+Rerank"三组准确率（论文消融实验）。

## 20. 智能助手 Tool Calling（Agent）

| 工具方法（Java） | 说明 |
|---|---|
| `queryNextFollowup(patientId)` | 查下次随访任务（Feign→followup-service） |
| `queryNoduleTrend(patientId)` | 查结节变化趋势 |
| `reportSymptom(patientId, symptom, severity)` | 症状上报入库，severity≥3 触发医生预警 |
| `queryReportSummary(patientId)` | 最近报告结论摘要 |

- 权限：工具内部强制以当前登录患者身份查询，防止"越权问别人数据"。
- 审计：每次工具调用落库 `ai_chat_message.tool_calls_json`。

## 21. 报告解读（A1）

- 输入结构化结节信息+报告结论，输出固定四段式：`这是什么 / 风险怎么看 / 下一步建议 / 注意事项`，末尾固定免责语。
- SSE 流式返回，前端打字机效果。

# 第五部分　非功能与可靠性设计

## 22. 安全设计

- **认证**：JWT（access 2h + refresh 7d），注销/改密后旧 Token 入 Redis 黑名单；密码 BCrypt。
- **授权**：RBAC（菜单+按钮+接口三级 `@PreAuthorize`）；患者侧接口强制数据权限（仅本人）。
- **脱敏**：身份证/手机号出参脱敏（`138****5678`）；AI 请求前文本脱敏过滤器。
- **审计**：登录、建档、计划调整、规则修改写操作日志。
- **传输**：HTTPS；附件下载走预签名 URL（MinIO，限时有效）。

## 23. 可靠性设计

| 场景 | 方案 |
|---|---|
| 提醒消息丢失/重复 | RocketMQ 延迟消息 + biz_key 幂等 + 死信队列 + 发送记录表对账 |
| 定时任务多实例重复执行 | XXL-Job 分片广播按 patient_id 取模分片 |
| 重复建档/重复生成计划 | Redisson 分布式锁（key=patientId）+ 数据库唯一索引兜底 |
| 跨服务一致性（建档+快照+计划） | Seata AT 全局事务；失败回滚并提示人工重试 |
| LLM API 不稳定 | Sentinel 熔断（超时 30s/异常比例 50%）→ 降级文案 + 待重试任务 |
| 热点数据（模板/规则/字典） | Caffeine(本地 5min) + Redis(30min) 两级缓存，布隆过滤器防穿透 |

## 24. 性能设计

- 随访工作台等列表全部分页；高频查询字段建组合索引（见 DDL）。
- 统计驾驶舱预聚合：XXL-Job 每小时生成统计快照表，接口直查快照。
- 目标：列表接口 RT < 1s（单服务 200 并发压测达标，JMeter 出对比报告）。

## 25. 可观测性

- SkyWalking Agent 接入全部服务，网关入口生成 TraceId 透传；
- 日志统一格式 `%d [%X{traceId}] %-5p %c - %m%n`，ELK 可选；
- Sentinel 控制台实时监控熔断/限流。

## 26. 部署方案

```yaml
# docker-compose 开发环境（一键起中间件）
services: [nacos, mysql, redis, rocketmq-namesrv, rocketmq-broker, minio, xxl-job, sentinel-dashboard]
# 应用服务本地 IDE 启动；生产可选 K8s + Nacos 集群
```

## 28. 答辩演示主线（建议）

1. 医生粘贴 CT 报告 → **AI 抽取**结构化结节 → 确认建档；
2. **规则引擎**自动匹配模板生成 3 年随访时间轴（打开 decision_rule 表证明非硬编码）；
3. 修改规则表某行间隔 → 重新生成计划即时生效（**表驱动深度点**）；
4. 模拟到点 → **延迟消息**推送复查提醒；
5. 录入复查：结节增大 3mm → 系统**自动升级随访级别**并预警医生；
6. 患者端问"我这种结节多久复查一次" → **RAG 回答附指南出处**；
7. 患者端"我最近咳嗽厉害，下次什么时候复查" → **Tool Calling** 查真实计划+上报症状+触发预警；
8. 断开 LLM 网络 → **Sentinel 熔断**优雅降级；展示压测对比图与消融实验表收尾。
